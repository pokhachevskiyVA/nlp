# Памятка: как делать прогон и что проверять

Написана после первого прогона по RR и полному набору (28.09.2026), когда за один
день нашлись три утечки подряд. Если идти по этому списку, вопросов возникать
не должно.

## Команда

```bash
cd outputs/_cache          # или Код_прогона — это копии одного и того же
python3 cpet.py --список-целей
python3 cpet.py --цель прирост --признаки rr --спорт оба --выход "Папка/Подпапка"
```

`--признаки`: `газ` | `rr` | `все`. `--спорт`: `оба` | `лыжники` | `баскет` |
`контроль` | `"все три"`. `--без-кластеров` — не делить на сильных и слабых.

Время: газ ≈ 20 с на цель для двух видов спорта, RR ≈ 40 с, полный набор ≈ 65 с.

## Что получается само

В каждой подгруппе: две плеяды, `Отчёт_краткий.html`, `Отчёт_полный.html`,
`Значимые_признаки.xlsx`, **`Квартили_значимых.xlsx`** и `_вход.xlsx`.
Свод по виду спорта — в корне папки вида спорта.

Страницы `00_Сводка.html`, `00_Начните_отсюда.html` и `Расшифровка_признаков.html`
собираются отдельно скриптами из `отчёты/`. **В них дата папки прописана строкой** —
при новом прогоне поправить.

## Обязательные проверки после прогона

Порядок такой, потому что каждая следующая имеет смысл только если прошла предыдущая.

### 1. Нет ли признака, который и есть цель

Автопроверка встроена: если Спирмен признака с целью выше 0,95 по модулю, в лог
печатается `ЗЕРКАЛО ЦЕЛИ: <имя> (|r| = …) — исключён`, и признак выбрасывается.
**Если такая строка появилась — не игнорировать**, а понять, почему признак
дублирует цель, и добавить его в `LEAK` по имени.

Так поймался `Н_всего_Sum` — сумма интервалов нагрузки, то есть её длительность
в миллисекундах, r = 1,000 с приростом.

### 2. Не просочилась ли утечка через заполняемость

Для целей, которые есть длительность теста (прирост, мощность и производные от
них), признак может течь не значением, а самим фактом наличия: период `9Н`
существует только у того, кто доехал до девятой минуты.

Проверка одной строкой:

```python
есть = pd.to_numeric(d[c], errors='coerce').notna().astype(int)
r = scipy.stats.pointbiserialr(есть[ok], Δ[ok])[0]     # |r| > 0,4 — утечка
```

Уже проверено и зашито: `1Н`–`5Н` чисты (заполнены у 100%), `6Н`–`9Н` исключены
для целей на длительности.

### 3. Сколько связей получилось бы случайно

При большом числе признаков это главный вопрос. Считает `отчёты/множественность.py`:

| набор | признаков | ожидаемо случайных при p < 0,05 |
|---|---|---|
| газ | ≈ 115 | ≈ 6 |
| rr | ≈ 550 | ≈ 28 |
| все | 750–1110 | 37–56 |

**Если значимых меньше или столько же, сколько ожидается случайно — связей нет.**
Так вышло с кислородной ценой прироста: 18 значимых при 27,7 ожидаемых.

В отчёт выносить не только число значимых, но и сколько переживает Бонферрони.

### 4. Диагностика «эффективностей»

Для любой цели вида «что-то на ватт» посчитать `r(цель, знаменатель)` и сверить
с тождеством `−√(1−ρ²)`, где `ρ = r(W, знаменатель)`. Подробности в
`ПОКАЗАТЕЛИ.md`, раздел 12. Если сходится — цель это переименованный знаменатель.

## Грабли, на которых уже стояли

**Перечисление имён в `LEAK` не ловит варианты.** Было `'ЧСС<100_HRR'`, а в
таблице появилась пересчитанная копия `газ_восст_ЧСС<100_нов_HRR` — подстрока не
совпала, признак встал ведущим в плеяде с r = +0,88, хотя по построению это
`ЧСС_пик − 100`. Теперь ловится регулярным выражением `LEAK_RE`.
**Признаки, заданные порогом или параметром, ловить шаблоном, а не списком.**

**Набор `rr` — это не «всё, что не газ».** Раньше туда попадали стабилометрия,
психология и антропометрия — почти 600 колонок, к ЭКГ отношения не имеющих.
Теперь наборы задаются доменами из `domains.py` (словарь `НАБОРЫ` в `cpet.py`).

**`Ннак_N3` нельзя вычитать из `КИ_за_нагрузку`.** Первое считается от начала
записи и включает предстарт со стартом, второе — от начала нагрузки; отрезок
0–60 с вычитается дважды. Для ударов за разгон есть готовый `КИ_за_разгон`.

**Доля момента внутри нагрузки считается от `load_start`,** а не от номинальных
60 с. Иначе получаются доли выше 100%.

**Кластеры «сильные/слабые» делятся по медиане своей цели**, поэтому их состав
у разных целей разный. Для сравнительных таблиц брать кластеры по одной цели
(мы берём по приросту) и говорить об этом явно.

## Персональные данные

Репозиторий `pokhachevskiyVA/nlp` **публичный**. Перед любым коммитом:

```bash
grep -rIl "Юдин\|Дружинин\|Зверков\|Адров\|<другие фамилии>" . --exclude-dir=.git
```

Не выкладывать: `разметка/` (в путях ФИО с отчествами и датами рождения),
`исключения.json`, любые `.rr` и `.xlsx`. Список исключаемых из целей лежит
в `исключения.json` рядом с таблицей, в репозитории только пример структуры.

## Выкладка

Один эксперимент — одна папка с датой в `Отчёты_CPET_RR/ФИНАЛ_ВСЕ/`, внутри по
наборам и целям. Старые папки не трогать, новое кладётся рядом. На Диске ничего
не удалять — устаревшие страницы заменять указателем на новое место.
